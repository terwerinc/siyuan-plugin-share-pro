# 周记归档

本页定义周记归档的专项流程。

## 适用范围

当任务涉及以下任何场景时，必须优先读取本页：

- 周记归档
- 未完成事项迁移
- 承接页整理
- 下一周页承接
- 归档页清理

## 归档的定义

周记归档至少包含以下动作：

1. 保留并整理当前周 **已完成** 内容
2. 将当前周 **全部未完成事项** 迁移到下一周页或用户指定承接页
3. 从当前周文档中**移除已迁移的未完成事项**
4. 将当前周文档改名为 `xxx-已归档`

如果未完成事项没有全量迁走，或归档页里还保留承接性内容，就不算归档完成。

## 归档前定位

先定位：

1. 当前周页
2. 下一周页
3. 如果用户指定了承接页，也要定位承接页

CLI 辅助：

```bash
# 列出周记所在目录，确认真实周记树结构
siyuan document list --notebook <nbID> --path <周记父路径> -w <ws> -f json
# 按标题找周页
siyuan document search "周记" -w <ws> -f json
```

规则：

- 默认优先迁入**下一周页**
- 如果用户明确指定承接页，则迁入承接页
- 如果下一周页不存在且用户也未指定承接目标，先确认，不自行猜测目标页
- 周记归档使用 **真实周记文档树，** 不要把 daily note 机制误用到周记归档

## 已完成 / 未完成判断

### 可以保留在归档页里的内容

- 已完成事项
- 阶段性成果
- 阶段性突破
- 已确认结论
- 必要复盘

### 必须迁走的内容

- 本周主线中仍未完成的项
- 其他工作中仍在推进的项
- 固定提醒中的未完成项
- 金融信息中的未完成项
- 学习与成长中的未完成项
- 当前周中所有进行时、承接式、待继续表述

### 遇到边界不清

如果无法可靠判断某条内容是否已完成：

- 停止归档
- 先确认

不要擅自把模糊事项归为“已完成”或“未完成”。

## 归档流程

1. 读取当前周全文：`siyuan block kramdown --id <当前周docID> -w <ws> -f json`
2. 识别所有未完成事项
3. 将未完成事项全量迁入下一周页或承接页：
   ```bash
   siyuan block append --parent <下一周docID> --file <迁移内容.md> -w <ws>
   ```
4. 重写当前周页，只保留历史资产
5. 从当前周文档中删除已迁走的块：
   ```bash
   siyuan block delete --id <已迁移blockID> -w <ws> --dry-run
   ```
6. 删除或改写以下承接性表述：
   - 未完成
   - 下一步
   - 待继续
   - 已结转到下周
   - 其他进行时语言
7. 重命名为 `-已归档`：
   ```bash
   siyuan document rename --id <当前周docID> --title "<原名>-已归档" -w <ws>
   ```

> 归档属于 **多步破坏性写操作** （含 `block delete`）。
> 执行前务必先 `siyuan repo create --memo "周记归档前快照"`，
> 并对每个 `block delete` 先跑 `--dry-run`。
> 同时遵守 `SKILL.md` 的 **pull → 操作 → push** 铁律。

## 每日记录规则

- 每日记录不是默认忽略项
- 如果当前仍能准确回忆，则正常整理
- 如果已经无法准确回忆，则不要倒推、不要补写、不要猜
- 必要时可以用周级总结替代无法确认的日级细节

## 归档页写法

归档页必须让人一眼看懂：

- 这周做成了什么
- 留下了什么结果
- 哪些结论已经确认

不要把归档页写成进行中的任务清单。

## 禁止事项

- 禁止只迁移一部分未完成事项
- 禁止在归档页继续保留已迁走的未完成事项
- 禁止补写记不清的历史事实
- 禁止保留空话、套话、姿态化总结

## 推荐最小结构

```markdown
## 本周日期
## 归档摘要
## 已完成事项
## 阶段性成果
## 已确认结论
## 复盘
```
