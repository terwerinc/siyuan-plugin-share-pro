# 写作规则

本页定义思源知识层的写法。

## 总原则

同时服务于：

- 人阅读
- AI 检索
- AI 复用

## 基础 Markdown 约定

- 默认使用纯 Markdown，不引入不必要的特殊格式
- 不重复 H1；思源文档标题已经承担 H1 作用，正文从 `##` 开始
- TODO 使用 checkbox：未完成 `- [ ]`，已完成 `- [x]`
- 多行内容写入遵守 `capabilities.md`：优先用 `--file <path>` 或 `--file -`（stdin），不要把 `\n` 当普通字符塞进 `--data`

## 内部链接

思源内部链接格式：

```markdown
[显示名称](siyuan://blocks/ID)
```

规则：

- 只有确知块 ID 时才写入内部链接
- 保留已有有效内部链接
- 不为了制造双链而虚构或猜测 ID

## 高价值句式

优先写成：

**对象 + 动作 + 结果 + 验证**

例如：

- 完成知识库业务实体数据结构扩展的一版代码实现，并通过一条关键 case 验证

## 应优先保留的信息

- 项目名
- 任务名
- 模块名
- 做了什么动作
- 产出了什么结果
- 是否完成代码
- 是否完成测试
- 哪条 case 通过 / 失败
- 使用了什么模型 / 工具 / 环境
- 当前阶段是什么

## 禁止写法

- 大话
- 空话
- 套话
- 只有姿态没有事实的句子

如无具体事实支撑，避免：

- 本周最大的收获是……
- 真正拉开差距的是……
- 留下来的核心资产是……

## 来源页写法

- 优先保留时间线
- 优先保留原始事实
- 可以追加，但不要静默改写旧事实

## 知识页写法

- 优先沉淀稳定结论
- 优先整理高频可复用事实
- 结论后面要能找到事实支撑

## 索引页 / 入口页写法

适用：

- 用户明确要求整理索引页、入口页、目录页
- 容器页需要从占位页升级为可读入口
- 母文件已有子文档，需要承担摘要和导航

规则：

- 母文件优先作为目录 / 摘要页，不额外滥建索引子页
- 索引内容直接放在母文件，除非用户明确要求单独索引页
- 快速入口优先使用表格或短列表，说明分类用途和可点击入口
- 结构说明可以用目录树表达，但只写真实存在或已确认的结构

推荐区块顺序：

```markdown
## 摘要
## 快速入口
## 近期活跃
## 结构说明
## 使用规则
```

## 归档页写法

只保留：

- 已完成事项
- 阶段成果
- 已确认结论
- 必要复盘

不要保留：

- 下一步
- 待继续
- 已结转
- 仍在推进

## 不确定内容处理

- 记不清就不要补
- 无法确认就先问
- 不要倒推、不要杜撰、不要 mock
